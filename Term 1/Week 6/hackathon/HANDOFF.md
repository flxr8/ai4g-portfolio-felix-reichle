# Weekend handoff: Bahn-Puls collector

## What's running
A GitHub Actions workflow runs every ~10 minutes. Each run searches Bluesky for
German rail posts, filters them, scores sentiment with two local models, and
pushes the database (`pulse.db`) plus a status report (`STATUS.md`) to the
`bahn-puls-data` branch. Nothing runs on our laptops.

Weekend goal: keep it running. We need 48 h of continuous operation and 300+ items
by Thursday.

## Where to look
- **Status report:** [`STATUS.md` on bahn-puls-data](https://github.com/flxr8/ai4g-portfolio-felix-reichle/blob/bahn-puls-data/STATUS.md).
  It is regenerated by every run and shows totals, items per day, the last
  successful run, recent errors and a verdict (`OK` / `PROBLEM`).
- **Run history:** [Actions → Bahn-Puls collector](https://github.com/flxr8/ai4g-portfolio-felix-reichle/actions/workflows/bahn-puls-collect.yml).
  Each run's **Summary** tab has the same report; the step logs have the details.
- **From a terminal (optional):** `python -m pulse.status --remote` downloads the
  live DB and prints the same report.

## What counts as a problem
| Signal | Meaning |
|---|---|
| Verdict `PROBLEM` | The report lists the reason (no successful run for 60 min, no new items for 6 h, models failing, or the last 3 runs failed). |
| `(checked …)` timestamp over ~1 h old | No run has published since then, so the scheduler stopped or runs are crashing early. Check the Actions tab. |
| Several consecutive red runs | Something is persistently broken; the step log shows where. |

Normal, no action needed:
- Gaps of 10–30 min between runs. GitHub's cron is best-effort.
- One red run between green ones, e.g. a network timeout.
- Very few new items overnight.

If something's wrong, message me with a screenshot or the error from the step log.
I'm offline until Monday, so if it's clearly broken, a quick message is enough.

## Please leave alone (and why)
- **The `bahn-puls-data` branch.** Each run force-pushes it, so manual commits
  there get overwritten, or worse, could corrupt the DB we restore from.
- **`main`.** The scheduler always runs the code on `main`, so a broken push stops
  collection until I'm back.
- **Settings → Secrets** (`BSKY_HANDLE`, `BSKY_APP_PASSWORD`): the Bluesky login.
- **"Disable workflow".** Obviously stops collection. Manually triggering an extra run
  with **Run workflow** is fine and harmless.
